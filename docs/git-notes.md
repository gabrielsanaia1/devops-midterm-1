# Git workflow notes

`--force-with-lease` remote ბრენჩის გადაწერამდე ამოწმებს, რომ მისი მდგომარეობა ემთხვევა ჩვენთვის ცნობილ მდგომარეობას; განსხვავების შემთხვევაში push-ს უარყოფს, ხოლო `--force` ამ დაცვას არ გვაძლევს.
Rebase არ უნდა გამოვიყენოთ შეთანხმების გარეშე გაზიარებულ კომიტებზე, რომლებზეც სხვა დეველოპერები უკვე მუშაობენ, რადგან ის ისტორიასა და კომიტების ჰეშებს ცვლის.
Value Stream-ის სცენარის გუნდისთვის ავირჩევდი trunk-based development-ს მოკლეხნიანი feature ბრენჩებითა და მცირე, ხშირი ინტეგრაციებით.
ავტომატურ CI შემოწმებებთან ერთად ეს მიდგომა შეამცირებდა დიდი ცვლილებების დაგროვებასა და ინტეგრაციის ლოდინს, რაც lead time-ის შემცირებას შეუწყობდა ხელს.
