# CI notes

## npm cache-ის შედარება

| Job | პირველი გაშვება | მეორე გაშვება |
|---|---:|---:|
| Node 22 | 12 წმ | 9 წმ |
| Node 24 | 12 წმ | 14 წმ |

ცხრილში მოცემულია job-ების სრული ხანგრძლივობა.
მეორე გაშვებაზე Node 22-ის ლოგში დადასტურდა `Cache hit` და `Cache restored successfully`; აღდგა დაახლოებით 9 MB npm cache.
Node 22-ის job 3 წამით აჩქარდა, ხოლო Node 24-ის job 2 წამით გახანგრძლივდა.
ამ ორი გაშვებით cache-ის სარგებლის ზუსტად შეფასება შეუძლებელია, რადგან სრული job-ის დრო სხვა ნაბიჯებსა და runner-ის მუშაობაზეც არის დამოკიდებული.

## Runner-ის არჩევანი

ამ პროექტისთვის ავირჩევდი GitHub-hosted (SaaS) runner-ს, რადგან არ გვჭირდება საკუთარი სერვერის გამართვა, განახლება და მოვლა.
ის საკმარისია npm დამოკიდებულებების დაყენებისა და Node 22/24-ზე ტესტების გასაშვებად.
Self-hosted runner-ს განვიხილავდი სპეციალური გარემოს ან შიდა ქსელის რესურსებზე წვდომის საჭიროებისას.
